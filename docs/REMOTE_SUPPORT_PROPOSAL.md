# 使用者授權遠端診斷與協助方案（提案）

> 狀態：草案，供產品決策使用；不代表已承諾實現。
>
> 適用範圍：Windows 優先的客戶電腦診斷與人工協助。
>
> 核心原則：客戶始終知情、可見、可拒絕、可隨時斷開；“全部權限”不是預設能力。

## 1. 要解決的問題

希望客戶安裝一個 Autoto 支援端後，技術支援人員能夠在客戶明確授權的前提下：

1. 檢視有限的裝置健康資訊和診斷報告；
2. 讓 Autoto 在客戶電腦上執行受控診斷任務；
3. 在客戶同意時協助執行修復操作；
4. 後續可選地檢視並操作客戶桌面；
5. 讓每次訪問都有可見狀態、時效、審計記錄和撤銷入口。

這不是隱藏控制、靜默常駐或繞過 Windows 安全機制的功能。客戶未授權、會話已結束或權限已撤銷時，支援人員不能繼續訪問裝置。

## 2. 結論與推薦範圍

推薦先做“**有人在場的遠端診斷**”，而不是直接做“全權限遠端接管”。

首個可交付版本應滿足：

- 僅支援 Windows；
- 客戶主動啟動支援端，且每次會話均顯示連線狀態；
- 支援人員只能訪問被授權的 Autoto Agent、專案和診斷資料；
- 支援傳送診斷任務、檢視結果，並對單次操作進行審批；
- 不提供螢幕控制、鍵盤滑鼠註入、後台常駐服務或管理員繞過；
- 會話預設短時有效，可由客戶或支援人員立即撤銷。

完成這一版本後，再根據真實支援需求決定是否投入桌面遠控和管理員級操作。

## 3. 現有基礎與缺口

### 3.1 已有基礎

倉庫中已存在兩類可以複用的能力：

| 能力 | 當前狀態 | 可複用價值 |
| --- | --- | --- |
| 遠端訪問 | 已實現 | 可通過 HTTPS 隧道訪問 Autoto；本機所有者可顯式開啟 `full` 會話。 |
| 遠端協作 / Peer Control | 底層實現處於 WIP | 一次性邀請、裝置身份、公鑰簽名、短期會話令牌、授權範圍、撤銷和審計。 |
| Agent 工具審批 | 已實現 | 支援將高風險工具呼叫置為待審批狀態，並記錄審批結果。 |
| 審計與權限模式 | 已實現 | 可作為支援操作和授權變更的審計基礎。 |
| 桌面殼 | 開發/內測可用 | 可作為客戶側支援端的外殼基礎。 |

現有 Peer Control 當前只支援受限的專案/Agent 協作：檢視脫敏快照、傳送任務、一次性審批。每個授權目前最多為 `readOnly` 或 `acceptEdits`，並不等於操作整個 Windows 桌面。

### 3.2 尚未實現的部分

以下能力尚未產品化，也不能向客戶承諾：

- 正式簽名的 Windows 安裝包、自動更新和解除安裝流程；
- 面向客戶的“輸入支援碼—確認授權—一鍵斷開”介面；
- 支援人員控制台與客戶裝置列表；
- 螢幕捕獲、鍵盤滑鼠控制、剪貼簿或檔案傳輸；
- Windows 服務、無人值守訪問和管理員安裝流程；
- UAC 提權的本地確認鏈路；
- 遠端支援專用中繼、頻寬控制、會話錄影和保留策略；
- 面向客戶支援場景的端到端測試、濫用防護和運維流程。

現有“遠端訪問 full 模式”適合裝置所有者遠端使用自己的 Autoto，不應直接作為面向客戶的遠端支援產品入口。

## 4. 目標使用者體驗

### 4.1 角色

- **客戶 / 裝置所有者**：安裝、啟動支援端，決定允許哪些能力，隨時結束會話。
- **支援人員 / 控制端**：在自己的 Autoto 支援控制台中發起或接收支援會話。
- **支援服務**：只負責配對、身份驗證、會話路由和審計；不應預設儲存客戶螢幕、檔案或命令輸出。

### 4.2 推薦會話流程

1. 支援人員建立一次性支援會話，生成短支援碼或連結。
2. 客戶從官方簽名來源下載並啟動支援端，輸入支援碼。
3. 支援端顯示支援人員的名稱、組織、裝置指紋、申請能力、有效時間和隱私說明。
4. 客戶逐項確認授權；未確認前，支援人員看不到客戶資料。
5. 雙方完成雙向身份校驗後建立短期會話。
6. 支援人員先獲取有限的診斷快照，再發送診斷任務。
7. 每個高影響操作按風險要求再次確認；需要管理員權限時由客戶在 Windows UAC 視窗本地確認。
8. 客戶可在支援端點選“立即斷開”；到期、撤銷、關閉支援端或網路中斷都會失效會話。
9. 會話結束後，客戶看到操作摘要；支援端清除短期會話憑證。

### 4.3 客戶側必須可見的內容

支援端應持續顯示：

- 當前是否有人連線；
- 連線的支援人員身份和指紋；
- 已允許的能力與到期時間；
- 最近執行的操作及結果摘要；
- “暫停”“斷開”“撤銷以後訪問”的入口；
- 隱私提示：哪些資料會被讀取、是否會儲存、儲存多久。

## 5. 權限模型

不要用一個“全部權限”開關覆蓋所有行為。應使用短期、分級、可撤銷的能力授權。

| 權限級別 | 示例能力 | 推薦首版狀態 | 授權要求 |
| --- | --- | --- | --- |
| `observe` | 基礎系統資訊、Agent 狀態、脫敏診斷日誌 | 支援 | 客戶一次確認，預設 30 分鐘到期。 |
| `run_diagnostics` | 執行固定的只讀診斷腳本、收集健康報告 | 支援 | 客戶一次確認；腳本必須有白名單和可讀說明。 |
| `approve_once` | 對某一次 Agent 工具呼叫批准或拒絕 | 支援 | 顯示操作類型、風險和目標，再單次確認。 |
| `apply_fix` | 修改配置、安裝依賴、重啟指定服務 | 後續 | 每項操作再次確認，必須保留審計。 |
| `desktop_control` | 檢視螢幕、滑鼠鍵盤協助 | 後續 | 客戶清楚確認、持續可見指示、預設有人在場。 |
| `elevated_action` | 需要管理員權限的操作 | 後續 | Windows 本地 UAC 確認；遠端不能繞過或代替確認。 |
| `unattended_access` | 客戶不在場時的訪問 | 最後評估 | 單獨產品能力，預設關閉，需要長期許可、裝置繫結和強審計。 |

`full` 不應作為支援端對外的權限名稱。即使以後提供完整協助，也必須由多個明確能力組合而成，並清楚告訴客戶實際影響。

## 6. 建議架構

### 6.1 客戶支援端

客戶支援端是一個獨立、簽名的 Windows 應用，職責包括：

- 顯示授權、連線和斷開狀態；
- 儲存裝置身份金鑰和有限的本地配置；
- 主動向支援服務建立出站加密連線，不要求客戶配置埠轉發；
- 收集經允許的診斷資訊；
- 將獲準的任務交給本機 Autoto Runtime 執行；
- 對螢幕控制、管理員操作等高風險能力執行本地確認；
- 在會話結束時撤銷短期憑證並停止資料流。

首版不安裝 Windows 服務、不設定開機自啟，也不在客戶關閉視窗後繼續執行。

### 6.2 支援人員控制台

支援人員控制台可以先作為 Autoto 內的一個模組，而不是單獨新應用。它需要：

- 建立會話和檢視會話狀態；
- 顯示客戶已授予的能力，而不是假定擁有權限；
- 檢視受限診斷快照和任務結果；
- 傳送任務、請求操作、檢視審批狀態；
- 終止會話、撤銷授權、匯出受限審計摘要；
- 對敏感操作要求支援人員再次確認。

### 6.3 配對與控制平面

建議在現有 `internal/peercontrol` 的裝置身份、邀請、挑戰和短期 bearer 憑證基礎上擴充：

- 每臺裝置都有獨立金鑰和可展示的指紋；
- 支援碼只能兌換一次，預設有效期 10 分鐘；
- 碼本身不是長期登入憑證；
- 客戶確認後才簽發會話令牌；
- 每次權限變更都遞增版本並使舊令牌失效；
- 支援端和控制端都應校驗對方身份和會話範圍；
- 所有訪問均寫入不可偽造的審計記錄。

產品化版本通常需要一個專用的會合/中繼服務，使客戶只需輸入短碼即可連線。現有臨時 Cloudflare 隧道可以用於原型驗證，但不應承擔完整客戶支援平台的賬戶、裝置和會話管理職責。

### 6.4 資料平面

診斷資料、Agent 訊息和審批應通過範圍受限的 API 傳輸。桌面影像和輸入控制若以後實現，應與控制平面分離：

- 使用端到端加密的資料通道；
- 預設不錄屏、不儲存剪貼簿、不自動上傳檔案；
- 網路受限時可走受控中繼；
- 對幀率、頻寬、檔案大小和會話時長設定上限；
- 斷連後立即停止輸入和螢幕傳輸。

在決定桌面遠控實現方式前，需要單獨評估自研 WebRTC、整合成熟遠控元件和使用 Windows 原生協議的安全、許可、維護與客戶體驗成本。不得為了快速實現而啟用客戶的公開 RDP、關閉防火牆或降低系統安全設定。

## 7. 診斷能力的首版邊界

為了讓首版真正可用，建議只提供可解釋、可審計的固定診斷項，例如：

- Windows 版本、硬體、磁碟空間、記憶體和網路連通性摘要；
- Autoto Runtime、Agent、Provider 和日誌健康狀態；
- 指定應用的版本、服務狀態和錯誤報告；
- 使用者主動選擇的日誌檔案或截圖；
- 明確白名單內的只讀 PowerShell / 命令列診斷。

以下操作不進入首版：

- 隱藏程序、靜默持久化、規避安全軟體；
- 掃描或上傳所有個人檔案；
- 自動讀取密碼、瀏覽器資料、金鑰或令牌；
- 自動以管理員身份執行任意命令；
- 未經再次確認的安裝、解除安裝、登錄檔修改或服務重啟。

## 8. 安全、隱私與合規要求

### 8.1 安全要求

- 客戶每次會話主動啟動或明確恢復支援端；
- 支援碼、邀請和短期會話令牌均不可重放；
- 裝置身份採用獨立金鑰，私鑰不離開裝置；
- 支援人員賬戶需要強身份驗證和最小角色權限；
- 所有權限、任務、審批、檔案請求、連線和斷開都寫入審計；
- 令牌、權限、裝置身份或支援人員賬號變化時，現有會話立即失效；
- 遠端輸入、任務和檔案路徑在客戶裝置的最終執行點重新校驗；
- 預設拒絕未知操作，審計寫入失敗時拒絕高風險授權；
- 客戶可在本機刪除裝置繫結和所有持久授權。

### 8.2 隱私要求

- 收集前明確說明資料類別、用途、儲存位置和保留期；
- 預設只傳輸完成診斷所需的最少資料；
- 日誌、截圖、檔案和命令輸出須脫敏、限長、加密傳輸；
- 禁止將客戶資料用於訓練、分析或營銷，除非取得單獨同意；
- 會話錄影、檔案傳輸和剪貼簿同步必須獨立開關；
- 支援結束後提供客戶可讀的會話摘要和刪除請求路徑。

### 8.3 管理員權限要求

管理員權限是 Windows 本機授權，不是遠端角色可以授予的能力。設計必須保證：

1. 客戶本機看到真實的 UAC 提示；
2. 遠端支援人員不能代替客戶點選或繞過 UAC；
3. 提權僅覆蓋當前明確操作，不自動轉為長期管理員會話；
4. 所有提權請求記錄操作目的、時間和結果；
5. 無法獲得本機確認時，應提供手工操作說明而非嘗試繞過。

## 9. 交付階段

### 階段 0：產品決策與安全評審

產出本提案確認版、威脅模型、隱私告知文案、支援人員角色規則和客戶授權介面原型。

### 階段 1：有人在場的診斷 MVP（推薦先做）

- 簽名的 Windows 支援端原型；
- 一次性支援碼和雙向身份展示；
- `observe`、`run_diagnostics`、`approve_once`；
- 支援任務傳送、診斷報告和會話審計；
- 客戶一鍵斷開、到期失效和撤銷；
- 不含桌面遠控、檔案傳輸或管理員操作。

驗收標準：客戶能在無埠轉發的普通網路中完成一次支援會話，並能清楚看到連線者、授權範圍、剩餘時間與斷開結果。

### 階段 2：受控修復

- 固定修復動作的請求與二次確認；
- 每個操作的前置檢查、預期影響和回滾說明；
- Windows UAC 本地確認；
- 更完整的審計摘要和支援人員角色控制。

驗收標準：任何可能改變系統的操作均可在客戶側看見、拒絕、追溯，並能在失敗時提供恢復路徑。

### 階段 3：有人在場的桌面協助

- 客戶授權後的螢幕檢視；
- 可選滑鼠鍵盤控制；
- 持續連線提示、暫停和斷開；
- 頻寬、剪貼簿、檔案傳輸和錄製的獨立開關。

驗收標準：斷開、鎖屏、授權變化或網路中斷後，遠端立即失去畫面與輸入能力。

### 階段 4：無人值守訪問（僅在確有需求時）

這是獨立的高風險產品線，不應自動從前述階段延伸。需要額外完成裝置所有者長期授權、企業賬號/角色、裝置清單、強認證、定期重新確認、異常訪問告警、審計保留和合規評審。

## 10. 需要在開工前確認的決策

1. 首版是否只服務 Windows，還是要相容 macOS/Linux？
2. 客戶是否必須全程在場？推薦“是”。
3. 首版是否僅做診斷，還是包含受控修復？推薦先僅診斷。
4. 是否需要螢幕控制？推薦作為階段 3 的獨立決策。
5. 支援人員是否只限內部團隊？推薦是，並使用組織賬號與強認證。
6. 客戶資料是否允許離開裝置儲存？推薦預設不儲存，只保留脫敏審計摘要。
7. 是否需要無人值守？推薦暫不做。
8. 採用自建中繼、受控雲服務，還是先以現有臨時隧道做原型？推薦原型使用現有基礎，產品版再建設專用會合服務。

## 11. 對現有程式碼的預期影響

如果決定實施，主要會涉及：

- `internal/peercontrol`：擴充支援碼、能力宣告、會話失效和雙向身份驗證；
- `internal/server/remote_collaboration.go` 與 `remote_peer_api.go`：新增支援會話、診斷和審計 API；
- `internal/db`：支援會話、授權、裝置、審計與保留策略的資料模型和遷移；
- `internal/desktop` / `cmd/autoto-desktop`：客戶授權、連線狀態、斷開和本地確認介面；
- 前端模組：支援人員控制台和客戶可讀的會話摘要；
- 釋出流程：Windows 安裝包、程式碼簽名、更新、解除安裝和安全響應流程；
- `SECURITY.md`、`README.md`、測試套件：更新邊界、威脅模型和端到端驗證。

這些工作會觸及遠端訪問和權限邊界，實施前應先通過獨立設計評審，而不是直接從現有 `full` 遠端模式擴充。

## 12. 建議的下一步

先確認本提案中的首版範圍。若認可“Windows + 有人在場 + 診斷優先”的方向，下一步可以拆出一個獨立的階段 1 實施計劃：介面原型、協議調整、資料模型、安裝包、測試和安全驗收標準分別評審。
